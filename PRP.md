* motion assets;
* large visual compositions.

It should:

* appear immediately;
* begin loading critical assets in the background;
* communicate meaningful progress;
* avoid relying only on a percentage;
* use changing microcopy;
* build curiosity;

# 36. ACCESSIBILITY

Despite the visual ambition, the product must remain accessible.

Consider:

* sufficient contrast;
* readable typography;
* semantic structure;
* keyboard navigation where relevant;
* focus states;
* accessible form labels;
* alternative text for meaningful images;
* non-color-only communication for critical states;

* border treatment;
* iconography;
* shape;
* opacity;
* accessible label.

Respect user reduced-motion preferences.

# 37. PERFORMANCE

This website may be visually ambitious, but it must not become a slow animation demo.

Prioritize:

* efficient asset loading;
* responsive images;
* appropriate image formats;
* lazy loading for below-the-fold media;
* preloading only genuinely critical assets;
* animation techniques suitable for the device;
* avoiding expensive continuous layout work;
* reducing effects on weaker devices;
* graceful fallback.

Do not load every 4K asset immediately.

The preloader is not permission to ignore performance.

The correct solution is:

> Optimize the experience, then use the preloader intelligently.

Evaluate animation complexity per device.
